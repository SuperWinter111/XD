# BMS 设计完成关口与开发启动条件

本文档用于明确三个问题：

1. 当前整体状态是否已经达到“设计完成”。
2. 如果希望直接推进到“设计完成阶段”，还缺哪些内容。
3. 当你把设计稿发送给 agent 或工程实现方时，什么条件下应直接开始开发，而不是继续补设计。

## 1. 当前整体结论

当前结论分两层：

1. 按 workPackage 维度：已经达到“可交付给 agent 开工”。
2. 按系统整体维度：当前基线已达到“整体设计完成”，但尚未进入联调完成阶段。

当前仓库的整体设计完成结论，以 [BMS_Design_Completion_Baseline.md](BMS_Design_Completion_Baseline.md) 为准。

因此当前状态更准确地说是：

1. 设计结构完成。

## 3. 要进入“设计完成阶段”还需要完成哪些部分

如果你的目标是把当前仓库推进到“设计完成阶段”，建议至少补齐以下 4 类内容。

### 3.1 工作包级具体 payload 样例

每个工作包至少补齐：

1. 1 套正常样例。
2. 1 套异常样例。
3. 1 套边界负样例。

当前这一步已完成，后续只需在开发阶段把这些样例从“基线资产”扩展为“真实执行记录”。

### 3.2 契约测试最小闭环

每个工作包至少要能从自己的目录追到：

1. 对应正式 ICD。
2. 对应 topic。
3. 对应 payload。
4. 对应样例文件。
5. 对应验收判断点。

如果不能从工作包目录一路追到最小测试件，则还不能说设计验收闭环完成。

### 3.3 主业务闭环多场景基线

当前已具备主业务闭环、运维治理、BFF 推送与恢复三类集成场景骨架；若要进入联调阶段，建议继续补齐：

1. 正常链路场景。
2. 异常回退场景。
3. 拒绝或降级场景。
4. 至少 1 条跨多个工作包的联调验收链路。

### 3.4 设计到实现的最终映射清单

建议补 1 份系统级总表，至少列清：

1. workPackage。
2. owner 对象。
3. 必发 topic。
4. 必读 topic。
5. 样例目录。
6. 最小验收件。
7. 开发启动状态。

这份总表不是为了增加文档数量，而是为了让“设计完成”可复核，而不是靠口头判断。

## 4. 明确的开发启动点

如果你把设计稿发给我，并要求我直接着手开发，下面这个判断口径最重要。

### 4.1 可以直接开始开发的条件

对单个工作包，只要同时满足以下条件，我就应直接开始开发，而不是继续追问设计：

1. 主工作包已稳定。
2. ICD_Package 已稳定。
3. Payload_Checklist 已稳定。
4. TODO 中已存在可执行任务。
5. 该工作包没有核心对象命名未定、topic 未定、owner 未定的问题。
6. testAssets 目录至少已有样例入口说明。

达到这 6 条时，我可以直接开始：

1. 建代码骨架。
2. 建 topic producer / consumer 框架。
3. 按 payload 清单定义数据结构。
4. 补最小契约测试样例。
5. 预留联调桩和 mock。

### 4.2 不应立即开始开发的条件

只要出现下面任一情况，我应先要求补设计，而不是直接写代码：

1. owner 归属未定。
2. topic 名称或 topic 边界未定。
3. payload 关键字段仍是待讨论状态。
4. TODO 只有讨论项，没有可执行项。
5. 同一对象在不同文档里有不同定义。
6. 样例入口完全不存在。

## 5. 面向你和我的明确 Go / No-Go 口径

当你说“我把设计稿发给你，请你着手开发”时，我建议按下面 3 档判断：

### 5.1 Go：立即开发

满足条件：

1. 已达到单工作包可交付标准。
2. 关键对象、topic、owner 已冻结。
3. TODO 已可执行。

我会直接进入实现，不再反复确认基础设计。

### 5.2 Go with Gaps：边开发边补测试资产

满足条件：

1. 主设计结构稳定。
2. 但具体样例文件不完整。
3. 异常或边界样例仍需补齐。

这是当前大多数工作包的真实状态。
在这个状态下，我可以直接开发，但要把“补样例”“补异常链路验证件”并入首批任务。

### 5.3 No-Go：先补设计

满足条件：

1. 主对象定义冲突。
2. owner 不清。
3. topic 不清。
4. 关键字段语义不清。

在这种情况下，不应直接开始开发。

## 6. 当前仓库的明确判断

截至当前，建议这样判断：

1. 单工作包开发启动：Go。
2. 全系统设计完成：已完成。
3. 全系统联调启动：尚未完成。

也就是说：

1. 你现在可以把工作包直接发给我开工。
2. 当前仓库已经可以作为后续开发的设计基线。

## 7. 建议的最后冲刺顺序

如果你的目标是尽快把仓库推进到“设计完成”，推荐顺序如下：

1. 先按工作包进入代码实现。
2. 再把现有基线样例升级为真实执行样例和回归记录。
3. 再补系统级开发启动状态总表或真实实施进度总表。
4. 最后把 STATUS 从“设计完成，可交付给 agent”升级为“可进入联调”。

## 8. 最终一句话标准

如果你发给我的材料，已经能让我不再追问“这个对象到底谁发”“这个字段能不能删”“这个异常怎么表达”，那我就应该直接开始开发。

如果这些问题还要靠口头补充，那就还没到真正的设计完成点。
