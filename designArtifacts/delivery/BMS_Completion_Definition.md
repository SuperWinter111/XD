# BMS 完成定义

本文档用于把“设计完成”“分系统可交付”“联调可进入”“系统级可验收”四类完成状态统一下来，避免不同负责人对“完成”的理解不一致。

## 1. 设计完成

一个分系统进入实现前，至少必须满足：

1. 已有 Container、Component、Code 图。
2. 已在追踪矩阵中标注对应正式 ICD、关键 topic 与联调对象。
3. 已明确主拥有对象、只读消费对象和禁止事项。
4. 已具备对应工作包或工作包模板化实例。

## 2. 分系统可交付

一个分系统实现任务只有在以下条件同时满足时，才可视为“可交付”：

1. Code 图中的核心模块已经落到实现或明确落到代码骨架。
2. topic 发布清单与订阅清单完整。
3. payload 与 schema / 正式 ICD 的绑定已核对。
4. 正常样例、异常样例、拒绝或超时样例至少各 1 套。
5. 契约测试已覆盖 topic、payload、字段语义和 trace_id。
6. 已说明 mock 方案何时被真实链路替代。
7. 文档已同步更新到对应 delivery、contract 或 schema 文档。

## 3. 可进入联调

一个分系统只有在以下条件满足后，才可以进入系统联调：

1. 上下游双方确认 payload 版本一致。
2. 联调矩阵中的本分系统相关链路已有验收样例。
3. 至少 1 条正常链路已在本地或子环境打通。
4. 至少 1 条异常链路已验证降级、拒绝或回退语义。
5. 已明确回滚方式、兼容策略与失败定位入口。

## 4. 系统级可验收

系统级验收至少必须满足：

1. 主业务闭环场景已跑通。
2. 关键跨分系统链路具备回归样例。
3. owner rule 未被破坏。
4. 正式 ICD、schema、topic 目录与实现一致。
5. 文档、样例、测试结果可供人类复核。

## 5. 不算完成的情况

以下情况一律不算完成：

1. 只有代码，没有对应文档更新。
2. 只有正常样例，没有异常样例或拒绝样例。
3. 只有 mock 打通，没有真实上下游联调计划。
4. 修改了公共 schema、topic 或 ownership，但没有影响分析与治理记录。
5. 通过私有旁路完成联调，未回到正式 ICD 与登记 topic。

## 6. 与工作包的关系

1. 各工作包中的“完成定义”必须至少满足本文档要求。
2. 如果某工作包存在更严格标准，可以加严，不能放宽。
3. agent 与工程师适用同一套完成定义。
