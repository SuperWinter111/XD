# BMS 任务、计划与异常语义说明

本文档用于固定 BMS 在后续 C4、Code Diagram 与接口设计中的基础语义，避免任务、计划、异常、人工介入等概念混用。

## 1. 任务与计划的语义边界

### 任务

任务用于描述行动目标与活动要求，重点表达“做什么、何时完成、达到什么效果”。

任务通常包含以下语义：

1. 任务目标。
2. 任务起始时间。
3. 任务终止时间。
4. 任务依赖关系。
5. 任务 MOE 指标。
6. 遍历周期、区域覆盖率等约束条件。
7. 任务分解链与资源分配前提。

任务不直接等价于末端可执行命令。

### 计划

计划用于描述末端平台可执行的具体执行语言，重点表达“怎么做、由谁做、按什么参数做”。

计划通常包含以下语义：

1. 航点与航路。
2. 编队与协同关系。
3. 传感器模式。
4. 武器使用方式。
5. 时间窗口下的执行参数。
6. 平台级执行动作序列。

计划必须满足任务约束，计划由交战管控分系统生成与调整。

## 2. 任务管理分系统与交战管控分系统职责边界

### 任务管理分系统

负责：

1. 指令解析。
2. 任务类型识别。
3. 任务分解。
4. 任务起止时间与 MOE 约束建模。
5. 任务资源匹配与分配前提生成。
6. 任务重构。

### 交战管控分系统

负责：

1. 接收任务约束。
2. 将任务语义转换为计划语义。
3. 生成交战计划。
4. 计划约束满足性校核。
5. 计划级调整。
6. 执行监控与异常分类。

## 3. 杀伤链任务

杀伤链应视为一种特殊任务流程，不是独立于任务管理分系统之外的旁路流程。

其特点是：

1. 有特定任务分解模式。
2. 任务链条由任务管理分系统拉起。
3. 交战管控分系统负责将杀伤链任务转换为具体交战计划。
4. 杀伤链任务与区域搜索、区域监视、防空压制等任务同属任务类型体系，但具有不同模板与约束结构。
5. 杀伤链任务可由态势事件自动触发，也可由人工标定目标后触发确认。

## 4. 计划级调整与任务级重构的分界

### 计划级调整

当末端执行出现异常时，如果交战管控分系统仍能在当前任务约束内生成新的可执行计划，则属于计划级调整。

### 任务级重构

只要异常导致当前计划调整后已不能满足任务约束，就必须回退至任务管理分系统进行任务重构。

任务重构通常包括：

1. 重新解析任务约束。
2. 重新分解子任务。
3. 重新匹配资源。
4. 重新形成任务链与任务约束。

## 5. 人工介入原则

人工可以在每一层次接入。

包括但不限于：

1. 人工调整任务目标与任务约束。
2. 人工调整计划内容。
3. 人工处理自动重构失败场景。

如果未来需要自动化执行，这些人工接口可以由前端自动脚本或策略代理替代，但语义上仍保留人工介入口。

## 6. 异常分类建议

当前建议统一纳入以下异常类型：

1. 资源异常。
2. 航路异常。
3. 链路异常。
4. 威胁异常。
5. 载荷异常。
6. 天气异常。
7. 禁飞区约束异常。
8. 敌情突变。
9. 平台失联。

建议后续继续补充以下异常类型：

1. 导航定位异常。
2. 授时同步异常。
3. 目标丢失或目标欺骗。
4. 武器不可用或挂载失配。
5. 传感器模式切换失败。
6. 协同成员掉队或编队失稳。
7. 燃油/电量不足。
8. 任务时窗违约风险。

## 7. 后续使用规则

1. 所有 Code Diagram 必须遵守本文档的任务与计划语义边界。
2. 所有异常处理逻辑优先判断是否属于计划级调整，否则转为任务级重构。
3. 所有人工介入点应在接口设计中明确保留。
4. 杀伤链任务的后续设计必须视为任务类型的一种，而非独立绕过任务管理分系统的旁路流程。
5. 杀伤链任务应同时支持自动触发与人工确认触发两种模式。
